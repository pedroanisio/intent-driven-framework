KEY DESIGN DECISIONS
================================================================================

1. UNIVERSAL vs DOMAIN-SPECIFIC
   • Root-level prose/tools = universal (apply to any domain)
   • Domain folders = specialized instantiations
   • Clear separation prevents software-specific leakage

2. FIVE DOMAINS IDENTIFIED
   • software (v1.6.1) — proven bootstrap
   • regulatory (v0.0.0) — high-fit candidate
   • product (v0.0.0) — high-fit candidate
   • ai-agent (v0.0.0) — medium-fit candidate
   • governance (v0.0.0) — medium-fit candidate, political unknowns

3. TEMPLATE FOR DOMAIN CREATORS
   • _template/ provides checklist + boilerplate
   • Copy → customize → test → document
   • Low friction for new domain research

4. VERIFICATION LAYER SEGREGATION
   • Zod, regex, NLP = universal tools (root)
   • Domain-specific tests = domain folders
   • Lean proofs = domain-specific (if applicable)
